# API 设计

## 1. API 风格

后端采用 REST API。公开接口与后台接口通过路径区分：

```text
/api/public/*   # 前台公开读取接口
/api/admin/*    # 后台管理接口，需要管理员鉴权
/api/auth/*     # 登录、刷新、退出
```

API 默认返回 JSON。上传使用 `multipart/form-data`。

## 2. 通用响应格式

### 成功响应

```json
{
  "data": {},
  "meta": {
    "requestId": "req_...",
    "timestamp": "2026-06-17T00:00:00.000Z"
  }
}
```

### 分页响应

```json
{
  "data": [],
  "pagination": {
    "page": 1,
    "pageSize": 20,
    "total": 128,
    "totalPages": 7
  },
  "meta": {
    "requestId": "req_..."
  }
}
```

### 错误响应

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "请求参数不合法",
    "details": []
  },
  "meta": {
    "requestId": "req_..."
  }
}
```

## 3. HTTP 状态码

| 状态码 | 场景 |
| --- | --- |
| 200 | 查询、更新成功 |
| 201 | 创建成功 |
| 204 | 删除成功，无响应体 |
| 400 | 请求参数错误 |
| 401 | 未登录或 Token 过期 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 409 | 唯一键冲突，如 slug 已存在 |
| 422 | 业务规则不满足 |
| 429 | 登录或上传频率限制 |
| 500 | 服务端错误 |

## 4. 鉴权设计

### Token

- Access Token：短期有效，建议 15 分钟。
- Refresh Token：长期有效，建议 14 天，可被撤销。
- 后台请求使用 `Authorization: Bearer <accessToken>`。
- Refresh Token 仅存储哈希值，避免数据库泄露后可直接使用。

### 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/auth/login` | 管理员登录 |
| `POST` | `/api/auth/refresh` | 刷新 Token |
| `POST` | `/api/auth/logout` | 注销当前会话 |
| `POST` | `/api/auth/logout-all` | 注销全部会话 |
| `GET` | `/api/auth/me` | 当前管理员信息 |

### 登录请求

```json
{
  "account": "admin@example.com",
  "password": "password",
  "captchaToken": "optional",
  "remember": true
}
```

> **PDF 导出方案（两阶段）**：MVP **不提供** `/resume/pdf` 服务端接口，改由前端 `/resume` 页面套用 `print.css` 触发浏览器“打印为 PDF”。此阶段 `resume_export_configs`（页边距、字体、主题色）建表但暂不接线，仅作数据预留。增强阶段再新增 `GET /api/public/resume/pdf`，由后端用 Puppeteer/无头浏览器按 `export_config` 渲染并返回 PDF 文件流。两套方案不要混用：要么纯前端打印，要么纯服务端生成。

## 7. 搜索与过滤约定

后台列表统一支持：

| 参数 | 说明 |
| --- | --- |
| `page` | 页码，默认 1 |
| `pageSize` | 每页数量，默认 20，最大 100 |
| `keyword` | 搜索关键词 |
| `status` | 内容状态 |
| `sortBy` | 排序字段 |
| `sortOrder` | `asc` 或 `desc` |

日期范围统一使用：

```text
createdFrom=2026-01-01&createdTo=2026-12-31
```

## 8. 契约管理

- 后端 DTO 使用 class-validator 或 Zod。
- 共享请求/响应类型输出到 `packages/contracts`。
- API 文档由 Swagger 自动生成，路径为 `/api/docs`。
- 前端 API client 只依赖 `packages/contracts`，不手写散落的 fetch。
