# 开发计划

## 1. 开发策略

采用“基础设施先行 + 垂直切片交付”的方式推进。

第一阶段先建立 monorepo、数据库、鉴权、媒体库和后台壳。随后每个业务模块都按“数据表 -> API -> 后台管理 -> 前台展示 -> 测试”的顺序交付，避免只完成 UI 或只完成接口。

## 2. 里程碑

### M0：工程初始化

目标：搭建可运行的前后端基础工程。

任务：

- 创建 pnpm workspace。
- 创建 `apps/web` Next.js 应用。
- 创建 `apps/api` NestJS 应用。
- 创建 `packages/contracts`、`packages/ui`、`packages/utils`。
- 配置 TypeScript、ESLint、Prettier。
- 配置 Docker Compose：PostgreSQL、Redis、MinIO。
- 配置环境变量样例 `.env.example`。

验收：

- `pnpm dev` 可同时启动 web 和 api。
- API `/health` 返回正常。
- Web 首页占位页可访问。

### M1：数据库、鉴权与后台壳

目标：管理员可以登录后台。

任务：

- Prisma schema 初版。
- Seed 默认管理员。
- Auth 模块：登录、刷新、退出、当前用户。
- 后台登录页。
- 后台基础布局：侧栏、顶部栏、路由保护。
- 操作日志基础表和登录日志。

验收：

- 未登录不能访问 `/admin/dashboard`。
- 登录成功进入后台。
- 登录失败记录日志。
- Token 过期处理正确。

### M2：媒体资源库

目标：全站内容可复用媒体能力。

任务：

- 媒体上传接口。
- S3/MinIO 存储服务。
- Sharp 图片处理任务。
- 媒体列表、搜索、文件夹。
- 媒体选择器组件。
- 引用计数基础能力。

验收：

- 后台可上传图片并看到缩略图。
- 图片生成多尺寸变体。
- 文章/图文/简历后续可复用 MediaPicker。

### M3：博客模块

目标：完成第一个完整内容闭环。

任务：

- 文章、分类、标签表和迁移。
- 博客后台 CRUD。
- Markdown 编辑器、封面选择、SEO 字段。
- 草稿、发布、回收站。
- 前台博客列表、详情、分类、标签、归档。
- Markdown 渲染、目录、阅读进度。

验收：

- 后台发布文章后前台可访问详情。
- 草稿不公开。
- 分类、标签筛选正确。
- 文章封面和正文图片正常加载。

### M4：图文笔记模块

目标：完成图文内容闭环。

任务：

- 笔记、图片、话题、统计表。
- 图文后台 CRUD。
- 多图上传和排序。
- 前台瀑布流。
- 详情页轮播和放大查看。
- 匿名点赞和浏览统计。

验收：

- 多图顺序稳定。
- 移动端浏览体验可用。
- 话题筛选正确。
- 统计能在后台看到。

### M5：简历模块

目标：结构化简历可后台维护、前台展示。

任务：

- 简历相关表。
- 后台简历编辑器。
- 分区排序和显示开关。
- 前台简历页。
- 打印样式和 PDF 导出入口。
- 首页简历摘要 API。

验收：

- 后台修改简历后前台同步。
- 打印排版无明显错位。
- 只有一个公开简历版本。

### M6：Landing Page 和前台整合

目标：完成产品设想中的视觉首页。

任务：

- 首页聚合接口。
- 前台导航和页脚。
- 3D Hero 第一版。
- 横向滚动内容卡片。
- 简历预览区。
- 博客和图文预览区。
- 暗色模式。

验收：

- 首页完整展示四大区块。
- 低性能设备有 fallback。
- 点击链路完整。
- 移动端无内容重叠。

### M7：统计、质量与发布

目标：达到可正式上线的稳定度。

任务：

- Dashboard 数据聚合。
- analytics rollup 任务。
- E2E 测试覆盖核心流程。
- 安全加固。
- SEO、sitemap、robots。
- 生产 Dockerfile 和部署文档。
- 数据备份和恢复演练。

验收：

- 主要流程测试通过。
- 页面基础 SEO 正常。
- 可以从空库部署并 seed。
- 有备份方案。

## 3. 建议开发顺序

```text
工程骨架
  -> 数据库迁移
  -> 鉴权
  -> 后台壳
  -> 媒体库
  -> 博客
  -> 图文
  -> 简历
  -> 首页
  -> 统计与上线
```

不要先做复杂 3D 首页。首页依赖博客、图文、简历的数据，过早开发会产生大量假数据和返工。

## 4. 每个模块的完成定义

一个模块只有同时满足下面条件才算完成：

- 数据表和迁移完成。
- 后端管理接口完成。
- 后端公开接口完成。
- 后台页面可维护。
- 前台页面可展示。
- 表单校验和错误处理完整。
- 基础测试通过。
- 文档中的验收标准通过。

## 5. 测试优先级

| 优先级 | 覆盖范围 |
| --- | --- |
| P0 | 登录、发布文章、上传媒体、公开访问文章 |
| P1 | 图文多图排序、简历编辑、站点设置 |
| P2 | 统计聚合、定时发布、首页 3D fallback |

## 6. 主要风险与对策

| 风险 | 对策 |
| --- | --- |
| 3D 首页耗时过长 | 放到 M6，先用静态 Hero fallback |
| 媒体处理复杂 | M2 独立完成，不与文章开发混在一起 |
| 后台 CRUD 重复工作多 | 抽象 DataTable、MediaPicker、StatusBadge、ConfirmDialog |
| Markdown 安全风险 | 后端清洗 HTML，前端渲染受控组件 |
| 单管理员扩展困难 | 数据表预留 role、operation_logs，但 MVP 不做复杂权限 |
| 图片删除误伤 | 引用计数 + 软删除 + 定期清理 |

## 7. 首批 Issue 拆分建议

1. 初始化 monorepo 和基础工具链。
2. 增加 Docker Compose 开发依赖。
3. 建立 Prisma schema 初版。
4. 实现管理员 seed。
5. 实现 Auth API。
6. 实现后台登录和 AdminShell。
7. 实现媒体上传和处理队列。
8. 实现博客文章 CRUD API。
9. 实现博客后台文章编辑页。
10. 实现公开博客列表和详情页。
